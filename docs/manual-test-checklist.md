# چک‌لیست تست دستی مالک

> وضعیت اولیهٔ همهٔ موارد زنده: **آزمایش نشد — مالک باید انجام دهد**. تست‌های محلی ۹۸/۹۸ سبز بوده‌اند، اما Telegram، Gemini، Cloudflare و `ai-exec.yml` واقعی در محیط توسعه اجرا نشده‌اند.

## ثبت شواهد بدون Secret

```text
تاریخ تست: [YOUR_TEST_DATE]
نسخه/Commit: [YOUR_COMMIT_SHA]
Worker URL: [YOUR_WORKER_URL]
مخزن هدف: [YOUR_GITHUB_OWNER]/[YOUR_TARGET_REPO]
PR تست: [YOUR_TEST_PR_URL]
Actions Run موفق: [YOUR_SUCCESS_RUN_URL]
Actions Run ناموفق: [YOUR_FAILURE_RUN_URL]
```

هیچ Token، API Key، Private Key یا محتوای Secret را در این فرم، چت یا اسکرین‌شات ننویس.

## ۰. پیش‌شرط امنیت

- [ ] CI واقعی PR سبز است؛ فقط به تست محلی تکیه نشده‌ام.
- [ ] `docs/security-review.md` را خوانده‌ام و موارد «پذیرفته شد/باقی‌مانده» را می‌دانم.
- [ ] `AI_DAILY_REQUEST_LIMIT = "50"` و `ACTIONS_MONTHLY_MINUTE_LIMIT = "100"` بررسی شده‌اند.
- [ ] هیچ Secret در `git diff`, `wrangler.toml`, لاگ یا چت نیست.
- [ ] این تست روی یک مخزن آزمایشی متعلق به خودم است، نه مخزن ناشناس.
- [ ] می‌دانم عامل توسعه هیچ Merge یا Deploy واقعی انجام نداده است.

## ۱. Worker و Webhook

- [ ] `GET [YOUR_WORKER_URL]/health` نتیجهٔ `"ok":true` می‌دهد.
- [ ] `getWebhookInfo` نتیجهٔ `ok:true` و URL مطابق `WEBHOOK_PATH` دارد؛ در تنظیم پیش‌فرض، `/webhook` نیز پذیرفته می‌شود.
- [ ] `last_error_message` خالی است و `pending_update_count` پیوسته رشد نمی‌کند.
- [ ] درخواست Webhook بدون Secret یا با Secret اشتباه ۴۰۱ می‌گیرد. این تست را بدون افشای Secret واقعی انجام بده.
- [ ] `npx wrangler tail` هیچ Secretی در لاگ نشان نمی‌دهد.

**شاهد/نتیجه:** `[YOUR_OBSERVATION]`

## ۲. احراز هویت مالک

- [ ] `/start` با حساب مالک پاسخ فارسی و منو می‌دهد.
- [ ] پیام از حساب غیرمجاز رد می‌شود و هیچ اطلاعات پروژه‌ای نمایش نمی‌دهد.
- [ ] Callback از حساب غیرمجاز رد می‌شود.
- [ ] در `audit_log` فقط رویداد `auth.denied` دیده می‌شود؛ هیچ Secret ثبت نشده است.

**شاهد/نتیجه:** `[YOUR_OBSERVATION]`

## ۳. ثبت پروژه و صف تحلیل

- [ ] `/project [YOUR_GITHUB_OWNER]/[YOUR_TARGET_REPO]` شاخهٔ پیش‌فرض درست را نشان می‌دهد.
- [ ] `/test_api` وضعیت Provider را بدون نمایش کلید می‌دهد.
- [ ] `/usage` بعد از `/test_api` شمارندهٔ درخواست AI را افزایش می‌دهد.
- [ ] بدون هیچ فرمانی بنویس «یک تغییر بسیار کوچک روی مخزن آزمایشی انجام بده» → ابتدا وضعیت «در صف تحلیل» می‌دهد (بدون نیاز به `/new`).
- [ ] «سلام، خوبی؟» را بنویس → فقط جواب چت می‌آید و هیچ درخواستی/هزینه‌ای ثبت نمی‌شود.
- [ ] «وضعیت چیه؟» را بنویس → گزارش وضعیت می‌آید (همان خروجی `/status`).
- [ ] جملهٔ مبهم (مثلاً «یه چیزی درباره لاگ‌ها») → به‌جای حدس زدن، سؤال کوتاه + دکمهٔ تأیید نشان می‌دهد.
- [ ] بعد از یک گفت‌وگو، «همون قبلی رو ادامه بده» → همان درخواست/زمینهٔ قبلی را در نظر می‌گیرد.
- [ ] پس از Cron، گزارش طرح فارسی با چهار دکمه می‌آید؛ تا چند دقیقه تأخیر را طبیعی بشمار اما لاگ را بررسی کن.
- [ ] قبل از تأیید، هیچ Branch، Commit یا PR جدیدی ساخته نشده است.
- [ ] `/tasks` وضعیت واقعی Job را نشان می‌دهد و Job ناموفق «موفق» گزارش نمی‌شود.

**شاهد/نتیجه:** `[YOUR_OBSERVATION]`

- [ ] دکمهٔ تأیید پیام قبلی با پیام خطای نسخه/انقضا رد می‌شود.
- [ ] فقط دکمهٔ نسخهٔ فعلی می‌تواند ادامه دهد.

## ۵. لغو — تست حساس و اجباری

- [ ] روی یک طرح تازه «لغو» بزن.
- [ ] پیام واقعی «لغو شد» دریافت می‌شود.
- [ ] وضعیت درخواست `cancelled` و وضعیت Approval `rejected` است.
- [ ] هیچ Branch، Commit، PR یا Job از نوع `execute` ساخته نمی‌شود.
- [ ] حالا دکمهٔ «تأیید و شروع» همان پیام قدیمی را بزن؛ باید رد شود.
- [ ] پس از چند دقیقه و یک Cron هم همچنان هیچ اجرایی رخ نمی‌دهد.
- [ ] دو بار پشت‌سرهم لغو بزن؛ بار دوم نباید تأیید تازه یا اجرای جدید بسازد.

**شاهد/نتیجه:** `[YOUR_OBSERVATION]`

> اگر هر نوشتن بعد از لغو دیدی، تست را Fail کن، تأیید تازه نزن و Branch/PR/Actions و لاگ را برای بررسی نگه دار. این مورد نباید «قبول با تفسیر» شود.

## ۶. تأیید واقعی و محدودهٔ تغییر

- [ ] یک درخواست تازه و بسیار کوچک بساز و فایل‌های Scope را بخوان.
- [ ] «تأیید و شروع» را بزن؛ یک Approval فقط یک‌بار مصرف می‌شود.
- [ ] دو کلیک نزدیک به هم دو اجرای مستقل ایجاد نمی‌کند.
- [ ] Branch با پیشوند `ai/` ساخته می‌شود، نه تغییر مستقیم روی `main`.
- [ ] فقط فایل‌های تأییدشده تغییر می‌کنند؛ فایل `.env`, Workflow یا Secret بدون Scope اضافه نمی‌شود.
- [ ] PR به شاخهٔ پیش‌فرض باز می‌شود ولی **Merge نمی‌شود**.
- [ ] متن PR درخواست/نسخهٔ طرح و وضعیت صادقانهٔ تست را دارد و Secret ندارد.

**شاهد/نتیجه:** `[YOUR_OBSERVATION]`

## ۷. `ai-exec.yml` واقعی — موفق و ناموفق

### Run موفق

- [ ] Run با `run-name` شامل Job ID دقیق پیدا می‌شود، نه فقط بر اساس Branch.
- [ ] Job `run` هیچ Secret رباتی در Environment ندارد.
- [ ] Job `report` Checkout ندارد و کد مخزن را اجرا نمی‌کند.
- [ ] نتیجهٔ موفق واقعی در Telegram/PR درج می‌شود.

### Run عمداً ناموفق

- [ ] در مخزن آزمایشی یک تست را عمداً Fail کن و Run را اجرا کن.
- [ ] Step فرمان Exit Code غیرصفر می‌دهد و Job/Run واقعاً Failure می‌شود.
- [ ] ربات «تست‌ها موفق بودند» نمی‌گوید.
- [ ] Artifact/Job Summary خروجی را محدود و بدون Secret نشان می‌دهد.
- [ ] Callback با Secret اشتباه ۴۰۱ می‌گیرد؛ Secret واقعی را برای تست در لاگ ننویس.

**شاهد/نتیجه:** `[YOUR_OBSERVATION]`

## ۸. سقف هزینه و رفتار صادقانه

- [ ] `/usage` تعداد درخواست AI را برای همهٔ Providerها مشترک نشان می‌دهد.
- [ ] یک `/test_api` هم مصرف را افزایش می‌دهد.
- [ ] سقف توکن/درخواست را با داشبورد واقعی Provider مقایسه کرده‌ام و می‌دانم یکی نیستند.
- [ ] `/usage` دقیقه‌های محلی Actions را نشان می‌دهد؛ آن را با Runهای واقعی و داشبورد GitHub مقایسه کرده‌ام.
- [ ] اگر Run پیدا نشود، می‌دانم رزرو ممکن است محافظه‌کارانه باقی بماند؛ شمارنده را بدون شاهد صفر نمی‌کنم.
- [ ] در نبود Provider آزاد، ربات وضعیت `failed` و راه بعدی را صادقانه می‌گوید و به مدل پولی خودکار نمی‌رود.
- [ ] هشدارهای Billing/Quota در پنل‌های واقعی فعال یا بررسی شده‌اند.

**شاهد/نتیجه:** `[YOUR_OBSERVATION]`

## ۹. حریم اسرار و بازیابی

- [ ] لاگ Worker، Audit، Job Log، Telegram و PR را برای الگوی Secret بررسی کرده‌ام.
- [ ] فایل‌های `.env`, `.pem`, `.key`, `.p8` و `.dev.vars` در Git نیستند.
- [ ] مسیر ابطال کلید را می‌دانم: Revoke در Provider، ثبت Secret جدید، Deploy و بررسی `/test_api`.
- [ ] پشتیبان D1 و نحوهٔ بازیابی را در سطح مورد نیاز خودم بررسی کرده‌ام.
- [ ] در صورت نشت، اسکرین‌شات یا لاگ را بدون حذف Secret منتشر نمی‌کنم.

- [ ] همهٔ موارد اجباری بالا با شاهد واقعی سبز شده‌اند.
- [ ] موارد انجام‌نشده صریحاً «آزمایش نشد» باقی مانده‌اند.
- [ ] هیچ یافتهٔ بحرانی باز ندارم.
- [ ] PR هنوز باز است و Merge فقط با تأیید جداگانهٔ من انجام خواهد شد.

نتیجه: [PASS / FAIL / NOT_TESTED]
