# گزارش بازبینی امنیتی

تاریخ بررسی: **۲۰۲۶-۱۰-۲۹**
دامنه: کد Worker، جریان Telegram، Approval، D1، AI Providerها، GitHub API، Workflowها، وابستگی‌ها و تنظیمات هزینه در همین PR.

> این سند یک بررسی کد و تست محلی است، نه گواهی امنیت Production. Telegram، Gemini، Cloudflare و اجرای واقعی `ai-exec.yml` در محیط بررسی **آزمایش نشده‌اند — مالک باید آن‌ها را انجام دهد**.

## نتیجهٔ کوتاه

- هیچ یافتهٔ بحرانیِ رفع‌نشده‌ای در مسیرهای بررسی‌شدهٔ محلی باقی نمانده است.
- کنترل‌های بحرانی قبل از اولین Deploy: Webhook Secret اجباری، Approval وابسته به درخواست/نسخه/انقضا، مصرف اتمیک، Scope دقیق فایل، جداسازی Secret از کد مخزن، و سقف‌های محلی ۵۰ درخواست AI و ۱۰۰ دقیقه Actions.
- موارد «باقی‌مانده» عمدتاً نیازمند اجرای واقعی یا تصمیم مالک‌اند؛ نباید آن‌ها را موفق فرض کرد.

## ریسک‌های **پذیرفته شد**

| ریسک | چرا پذیرفته می‌شود | شرط پذیرش |
|---|---|---|
| `npm test`, `pytest` و نصب وابستگی، کد مخزن را اجرا می‌کنند؛ Allowlist فقط نام فرمان را محدود می‌کند و کد پروژه را بی‌خطر نمی‌کند. | اجرای تست بخش لازم محصول است. | فقط مخزن مالک و پس از تأیید او؛ Job بدون Secret ربات، `contents: read` و `persist-credentials: false`. برای مخزن ناشناس استفاده نشود. |
| سقفهای AI/Actions محلی‌اند و صورتحساب یا مصرف خارج از ربات را نمی‌بینند. | API یکسان و قابل‌اعتمادی برای همهٔ حساب‌ها وجود ندارد. | مالک باید داشبورد Gemini/GitHub/Cloudflare را بررسی کند؛ این اعداد تضمین هزینهٔ صفر نیستند. |
| اگر Run بعد از Dispatch پیدا نشود، رزرو ۱۶ دقیقه باقی می‌ماند و ممکن است ربات زودتر متوقف شود. | آزادسازی در این وضعیت می‌تواند سقف را دور بزند؛ خطا به نفع امنیت هزینه است. | بررسی `/usage` و Actions توسط مالک؛ تغییر دستی شمارنده فقط با شواهد. |
| Callback Actions از Secret مشترک روی HTTPS استفاده می‌کند، نه امضای زمانی دار با جلوگیری کامل از Replay. | بدون Secret قابل جعل نیست و Jobها نتیجهٔ محدود دارند. | Secret بلند و خصوصی، URL فقط HTTPS، چرخش در صورت نشت؛ لاگ واقعی باید بررسی شود. |
| شمارش تماس Failشدهٔ AI هم در سقف ۵۰ باقی می‌ماند. | تلاش خارجی انجام شده و شمارش محافظه‌کارانه است. | ممکن است ظرفیت روزانه زودتر تمام شود؛ افزایش سقف فقط با تصمیم مالک. |
| لاگ دیباگ موجود `INCOMING UPDATE` محتوای پیام تلگرام را ثبت می‌کند و ممکن است شامل دادهٔ حساس باشد. | برای عیب‌یابی فعلی نگه داشته شده است. | دسترسی به لاگ محدود شود و این لاگ پس از عیب‌یابی حذف شود؛ Token یا Secret در پیام آزمایشی ارسال نشود. |

## گیت‌های لازم پیش از Deploy

- [ ] `TELEGRAM_WEBHOOK_SECRET` مقدار تصادفی و غیرخالی دارد.
- [ ] `AI_DAILY_REQUEST_LIMIT = "50"` و `ACTIONS_MONTHLY_MINUTE_LIMIT = "100"` تغییر نکرده‌اند، یا مالک آگاهانه مقدار دیگری را تأیید کرده است.
- [ ] هیچ Secret در `wrangler.toml`, Git، لاگ، چت یا آرگومان `wrangler secret put` قرار نگرفته است.
- [ ] `ai-exec.yml` همین نسخه در مخزن هدف کپی شده و Job اجرای تست به Secret ربات دسترسی ندارد.
- [ ] `BOT_CALLBACK_URL` با HTTPS و مسیر `/actions/callback` تنظیم شده است.
- [ ] CI واقعی PR سبز شده و چک‌لیست دستی تکمیل شده است.
- [ ] هیچ PR یا Deploy بدون تأیید جداگانهٔ مالک Merge/انجام نشده است.
