# عیب‌یابی

## ربات پاسخ نمی‌دهد

| نشانه | علت احتمالی | بررسی |
|---|---|---|
| هیچ پیامی نمی‌آید | وب‌هوک ثبت نشده یا آدرس اشتباه است | `curl "https://api.telegram.org/bot<TOKEN>/getWebhookInfo"` |
| `last_error_message` پر است | Worker خطا می‌دهد یا مسیر اشتباه است | مسیر باید برابر `WEBHOOK_PATH` (پیش‌فرض `/telegram/webhook`) باشد |
| خطای ۴۰۱ در لاگ Worker | سرّ وب‌هوک mismatch است | مقدار `x-telegram-bot-api-secret-token` باید برابر `TELEGRAM_WEBHOOK_SECRET` باشد |
| `{"ok":false,"error":"not found"}` | مسیر یا متد اشتباه | فقط `POST` روی مسیر وب‌هوک و `GET /health` معتبر است |

```bash
curl https://<worker>.workers.dev/health
npx wrangler tail    # لاگ زنده
```

## «شما اجازه استفاده از این ربات را ندارید»

- مقدار `OWNER_TELEGRAM_ID` باید **فقط عدد** باشد (شناسه از `@userinfobot`).
- چند شناسه را با کاما جدا کنید: `1001,2002`.
- پیام‌های گروهی هم بررسی می‌شوند؛ فرستنده باید مالک باشد.

## «هیچ ارائه‌دهنده رایگانی در دسترس نیست»

یعنی یا کلیدی تنظیم نشده، یا سقف روزانه/ماهانه پر شده، یا کلید نامعتبر است.

```
/test_api      # وضعیت تک‌تک کلیدها
/usage         # مصرف امروز و ماه
/models        # آیا ارائه‌دهنده‌ای فعال هست؟
```

اگر کلید نامعتبر باشد، ربات آن را غیرفعال و به شما اطلاع می‌دهد (بدون نمایش کلید).
کلید جدید بسازید و `npx wrangler secret put ...` را تکرار کنید.

## «تحلیل مخزن انجام نشد»

- دسترسی گیت‌هاب ندارید (App نصب نیست یا PAT محدود است) → `/github`.
- شاخهٔ پیش‌فرض اشتباه است → `/project owner/repo` را دوباره بزنید تا از API خوانده شود.
- مدل خروجی JSON معتبر نداده → ربات خطا را می‌گوید و درخواست را `failed` می‌کند
  (هرگز وانمود نمی‌کند موفق بوده است). یک بار دیگر `/new` را بزنید یا مدل را عوض کنید:

```
/provider gemini
/model gemini-1.5-flash
```

## «تستی اجرا نشد (workflow پیدا نشد)»

فایل `.github/workflows/ai-exec.yml` را در مخزن هدف کپی کنید و متغیرهای
`BOT_CALLBACK_URL` و سکرِت `ACTIONS_CALLBACK_TOKEN` را در تنظیمات Actions همان مخزن
اضافه کنید. کد و PR ساخته می‌شوند، اما تست اجرا نمی‌شود تا workflow وجود داشته باشد.

## «دستورهای ردشده (خارج از لیست مجاز)»

مدل دستوری پیشنهاد داده که مجاز نیست. لیست مجاز را گسترش دهید:

```toml
# wrangler.toml
COMMAND_ALLOWLIST = "npm test,pytest,npm run lint,python -m pytest"
```

و همان مقدار را در `.github/workflows/ai-exec.yml` هم به‌روزرسانی کنید
(CI هم‌زمانی این دو را چک می‌کند).

## «سقف Actions پر شده»

مصرف را ببینید: `/usage`. سقف را در `wrangler.toml` تغییر دهید یا تا ماه بعد صبر کنید.
برای مخزن عمومی، دقیقه‌ها نامحدودند (با Fair Use) — می‌توانید مخزن را عمومی کنید
یا سقف را بالا ببرید.

## کار در صف مانده و انجام نمی‌شود

- کرون هر ۵ دقیقه صف را تخلیه می‌کند: `npx wrangler tail` را ببینید.
- اگر وظیفه مرده است (`dead`): `/tasks` را ببینید؛ دلیل در `last_error` ثبت شده است.

## کلید لو رفت

1. در پنل ارائه‌دهنده کلید را باطل کنید.
2. کلید جدید بسازید و در Secrets قرار دهید.
3. `npx wrangler deploy`.
4. در صورت نیاز `audit_log` را بررسی کنید.

## خطای پایگاه‌داده

- آیا مایگریشن اعمال شده؟ `npm run db:migrate`
- آیا `database_id` در `wrangler.toml` درست است؟
- برای توسعهٔ محلی: `npm run db:migrate:local`.
